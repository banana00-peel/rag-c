# Roborock RAG

Roborock 石头扫地机器人中文官方说明书问答系统，面向实习简历展示的本地可运行 RAG 项目。

## 功能特性

- 支持上传 PDF 说明书，并自动识别品牌和型号，用户可在前端确认或修改。
- 使用 SHA-256 文件哈希去重，支持新增文档的增量索引。
- 按页解析 PDF，并在文本分块中保留文档名、型号和页码。
- 使用 Chroma 进行向量检索。
- 使用 BM25 进行关键词检索。
- 使用 RRF 对向量检索和关键词检索结果进行融合排序。
- 支持返回 Dense、BM25 和 RRF 分数，便于验证检索结果。
- 支持召回内容去重、相邻分块合并和单文档上下文配额。
- 支持型号别名归一化后进行元数据过滤。
- 明确区分无召回、低相关度和检索后证据不足三种拒答状态。
- 使用 Pydantic 校验 DeepSeek 结构化生成结果，不依赖自然语言关键词推断拒答。
- 支持基于 SQLite 的有界短期记忆，可将“那滤网呢”等追问改写为独立检索问题。
- 会话历史只用于消解指代，回答仍会重新检索并执行可信引用校验。
- 支持删除文档、失败重试、重新索引和中断任务恢复。
- 使用 DeepSeek 官方 API 生成中文客服回答。
- 使用 React + Vite 构建前端页面。
- 使用 LangGraph 编排问答流程。
- 提供版本化离线评测集，分别评测 Dense、BM25、RRF、拒答和可信引用。

## 环境要求

- Python 3.11 或更高版本
- Node.js 20 或更高版本
- DeepSeek API 密钥
- 支持 OpenAI-compatible `/v1/embeddings` 接口的 Embedding API 密钥

## 启动后端

```powershell
uv venv
.\.venv\Scripts\Activate.ps1
uv pip install -e .
Copy-Item .env.example .env
uv run uvicorn app.main:app --app-dir backend --reload --port 8000
```

索引文档前，需要先在 `.env` 中填写 `DEEPSEEK_API_KEY` 和 Embedding 服务配置。

## 启动前端

```powershell
cd frontend
npm install
npm run dev
```

浏览器打开：

```text
http://127.0.0.1:5173
```

## 首次使用流程

1. 上传 Roborock 石头官方 PDF 说明书。
2. 确认或修改系统识别出的品牌和型号。
3. 点击“保存并开始索引”。
4. 在问答区选择指定型号，或选择“全部型号”进行跨型号检索。
5. 输入中文问题，查看回答以及返回的文档名和页码来源。
6. 可继续输入省略型号或对象的追问，也可点击“新建会话”清空当前上下文。

## 当前版本范围

首版暂不包含 OCR、图片理解、联网搜索、登录鉴权、长期用户记忆和跨设备会话同步。

## 短期会话记忆

前端为每个新会话生成 UUID，后端使用该 ID 从 SQLite 读取最近的完整问答轮次。存在历史时，DeepSeek 只负责把当前追问改写成独立问题，例如将“那滤网呢”改写为“G20 的滤网应该如何清理”。独立问题随后重新进入型号分析、Dense + BM25 + RRF 检索、证据门控、生成和引用校验链路。

默认边界：

- 最多读取最近 6 个完整问答轮次。
- 输入改写器的历史总长度不超过 6000 个字符。
- 会话 60 分钟无新消息后过期，应用启动时清理过期数据。
- 问题改写失败时降级为原问题，不阻断现有单轮 RAG。
- 历史中的模型回答不作为事实证据，不能绕过本轮可信引用校验。

可以通过 `.env` 中的 `CONVERSATION_HISTORY_TURNS`、`CONVERSATION_HISTORY_MAX_CHARS` 和 `CONVERSATION_TTL_MINUTES` 调整这些边界。

## 离线评测

项目提供 30 条人工标注的 G20 v2 评测集，使用文档 SHA-256 和 PDF 物理页码作为稳定的正确答案位置。评测集划分为 20 条校准样本和 10 条独立测试样本，避免使用同一批数据调参并报告结果。v1 数据集及报告保留为结构化拒答改造前基线。

只运行检索评测：

```powershell
uv run python -m app.evaluation.cli `
  --dataset evaluation/datasets/g20_v2.jsonl `
  --mode retrieval
```

运行包含 DeepSeek 回答和可信引用校验的端到端评测：

```powershell
uv run python -m app.evaluation.cli `
  --dataset evaluation/datasets/g20_v2.jsonl `
  --mode end-to-end
```

2026-10-18 v2 基线结果：

- 测试集 Dense、BM25、RRF 和最终上下文的 Hit@5 均为 100%。
- 测试集 RRF MRR@5 为 0.917。
- 可回答问题的可信引用正确页命中率为 100%。
- 平均引用精确率为 95.0%，平均关键事实覆盖率为 97.5%。
- 结构化拒答准确率由 v1 的 20% 提升到 100%。
- 拒答样本中的引用校验失败数由 4 降为 0，未结构化自然语言拒答数为 0。
- 端到端成功率由 v1 的 86.7% 提升到 100%。
- 测试集检索门控拒答率仍为 50%，被放行的问题由生成阶段的证据门控正确拒答。
- 校准集得到的候选阈值没有改善独立测试结果，因此没有修改线上阈值。

详细结果见 `evaluation/baselines/`。该结果只代表当前一份 G20 说明书、当前评测集、模型版本与参数，不代表多文档或跨型号场景的泛化能力。

## 后续扩展方向

- 将评测集扩展到 50 到 100 条，并增加其他型号说明书。
- 扩展知识库外和边界问题，继续校准检索门控与生成证据门控的职责。
- 在有评测基线后验证轻量重排器是否带来稳定收益。
- 根据部署规模将进程内后台任务替换为独立任务队列。
- 支持 FAQ 网页采集。
- 支持用户会话历史和长期记忆。
